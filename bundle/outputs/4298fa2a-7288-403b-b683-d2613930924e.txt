**Places where the types were not obvious:**

- **`normalizeTool` (`src/validate.ts`)** — the raw record is `unknown` and deliberately under-checked. The original only checks `borrower` for *truthiness* (not `typeof === "string"`) and `category`/`retiredReason` with bare `||` fallbacks, so a numeric borrower or category would be stored as-is. I kept that behavior exactly and used narrow `as` casts after the original checks rather than tightening validation, which would have changed error behavior on weird inputs. Only `name` and `status` get real narrowing (via locals, since type-predicate narrowing on `Record` index access is unreliable).
- **`ToolStore.load` (`src/store.ts`)** — the parsed JSON is `unknown`; `raw.tools` is cast-checked just enough to reproduce the original `(raw.tools || []).map(...)` shape (a truthy non-array still throws `TypeError`, same as before). Same for `nextId` (a non-number would have been stored verbatim, so it stays cast, not coerced) and for the `catch (err)` blocks, where `err` is `unknown` under `useUnknownInCatchVariables`.
- **Nullable fields vs. invariants** — `Tool.dueDate`/`borrower` are typed `string | null`, but several places rely on the invariant "loaned ⇒ due date present": `returnTool` needs `daysBetween(tool.dueDate, …)` and `overdueTools` sorts on `a.dueDate.localeCompare`. I used a `tool is Tool & { dueDate: string }` filter predicate in `overdueTools` (the filter check was there anyway) and one `as string` in `returnTool`, matching the original's unchecked assumption.
- **`report.ts`** — `byStatus` starts as `{}` and is filled in a loop, so it's `{} as Record<Status, number>`; `priced` uses a type-predicate filter (`Tool & { replacementCost: number }`) so `insuredValue` sums without re-checking; `detail()`'s `tool.retiredReason` needed an `as string` since it's nullable on the type but always set for retired tools.
- **Flag typing (`src/cli.ts`)** — `parseArgs` yields `Record<string, string | true>` because a bare `--flag` becomes `true`. That leaks into `findTools`, whose `status` option is `string | true` (so `--status` with no value still throws `unknown status "true"`); `text`/`tag` get `as string | undefined` casts in the CLI to preserve the original's crash-on-`true` semantics for `--search` without a value.
- **`StoreEvent`** — a discriminated union on `type` (`added`/`loaned`/`returned`/`retired`); `returned` carries `borrower: string | null` because it's captured off the `Tool` type, even though it's never actually null at runtime.
