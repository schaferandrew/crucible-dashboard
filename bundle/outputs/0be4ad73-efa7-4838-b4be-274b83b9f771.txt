## Diagnosis

`app/page.tsx` was a **Server Component** (no `"use client"` directive) but used `useState`, `useEffect`, and browser `fetch` — all Client-Component-only APIs. Next.js threw at render time:

```
⨯ useState only works in Client Components. Add the "use client" directive...
```

so the page crashed into an error boundary (a 404 shell) and acct_1's name/plan never appeared. A secondary type error (`useState(null)` → `account` narrows to `never`) also broke `next build`.

## Fix (idiomatic App Router: server-side data access)

- **`lib/accounts.ts`** (new): the simulated database + `getAccount(id)`, shared as a single source of truth.
- **`app/page.tsx`**: now a plain Server Component that reads `getAccount('acct_1')` at render time and renders the same markup (`main`/`h1`/Name/Plan). No hooks, no client fetch — data is in the initial HTML (route prerenders as static).
- **`app/api/account/route.ts`**: unchanged behavior (200 with JSON / 404 for missing or unknown id), now backed by the shared module.
