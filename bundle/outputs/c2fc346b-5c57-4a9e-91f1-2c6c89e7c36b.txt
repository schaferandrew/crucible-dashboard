## What changed

**Deleted:** the whole `pages/` folder (`_app`, `_document`, `index`, `about`, `search`, `404`, `books/[slug]`, `genres/[genre]`, `api/books`).

**New `app/` structure:**
- `app/layout.tsx` — root layout with `<html lang="en">`/`<body>` (replaces `_app` + `_document`), imports `styles/globals.css`, wraps everything in the shared `Layout`.
- `app/page.tsx` — home, statically prerendered at build (was `getStaticProps`). Uses the `metadata` export for title/description.
- `app/genres/[genre]/page.tsx` — `generateStaticParams` + `export const dynamicParams = false`, which reproduces `getStaticPaths` with `fallback: false`: the three genres are built ahead of time, anything else is a straight 404.
- `app/books/[slug]/page.tsx` — `export const dynamic = "force-dynamic"` (was `getServerSideProps`), so it's server-rendered per request; unknown slugs call `notFound()` → 404. Metadata comes from `generateMetadata`.
- `app/about/page.tsx`, `app/not-found.tsx` — static, with their original title/description metadata.
- `app/search/page.tsx` + `app/search/SearchForm.tsx` — the client-side search (its shell was static before and still is). The form is a client component wrapped in `<Suspense>` (required for `useSearchParams`); the server page holds the metadata.
- `app/api/books/route.ts` — GET handler returning 200/400 as before, plus explicit 405 handlers with an `Allow: GET` header for POST/PUT/PATCH/DELETE/HEAD/OPTIONS.

**Component tweaks (`components/` only):**
- `Layout.tsx` is now a client component using `usePathname()` instead of `useRouter().pathname`; the active-link logic (`aria-current="page"`) is unchanged, and I verified each page marks the same link as current.
- `ShareLink.tsx` now takes the `slug` as a prop instead of reading `useRouter().query`, producing identical HTML.

**Verified with `next start`:** all URLs return the same status codes (200s, 404 for unknown book/genre/any path, API 400 for bad genre incl. repeated params, 405 for non-GET), titles/descriptions/nav HTML match, the view counter increments on every request, and `npm test` (7 tests) and `npm run build` both pass. No dependencies added; package.json, lockfile and config files untouched.

**Minor differences:**
- The App Router emits its RSC flight-data `<script>` payloads in the HTML, so byte-level HTML differs even though the visible markup is identical.
- The 404 "Back to the shop" link is a plain `<a>` (renders identical HTML to `Link`); unknown URLs now get served via `app/not-found.tsx`.
- `next-env.d.ts` was auto-regenerated by Next during the build (one doc-comment URL) — not a manual change.
